# 工作流 4：数字对账（number reconciliation）

**适用场景**：写报告、评分材料、汇报时引用资源占用、准确率、延迟、频率、位宽等数字。

## 用法

```text
报告里的每个数字都要有：值、单位、分母/口径、来源文件、测量条件。
同一指标的两个版本必须从同一份原始报告、同一工具读出。
数值题先看代码里有没有现成函数，用它的结果；手算只做交叉核对。
更正时给出完整正确表，并说明结论是否受影响。
```

步骤：

1. 列出要引用的数字，每个旁边写“出处”（报告文件 / 日志 / 脚本输出）。
2. 能脚本提取的用脚本提取（本项目：`skill/check_scripts/summarize_builds.py` 读 6 次构建的原始利用率与时序报告生成表）。
3. 对账：把文档里的数字与脚本输出逐项比对；口径不同的（BRAM 按 RAMB36 还是按 tile）写明。
4. 重要数字再用**独立路径**复核一次（本项目：从交付源码重新构建，重算同一组数字）。
5. 没测的写“未测”。

## 已验证效果

* BRAM 占比 65.7 % → 66.67 %（案例 06）：口径更正，此后所有文档使用同一组数字。
* 每计数微伏数（案例 03B）：用代码函数取值，手算错误被发现并更正。
* 交付包的重建验证：LUT 38,595、FF 50,125、RAMB36 142、RAMB18 4、DSP 64、WNS +3.129 / WHS +0.009 与原始构建完全相同（`build/reports/rebuild_check/`）。

## 失效条件

* 原始报告格式变化（如工具升级）时，提取脚本需要更新；提取不到时要报错，不能返回默认值。
* 数字来自不同测量条件（开发机 vs 板上 A53）时不能直接对比，必须在表里标注条件。
