# 工作流 3：声明必须配证据（claim needs evidence）

**适用场景**：模型要在汇报里写“已修好 / 已验证 / 不会发生 / 性能提升”。

## 用法

```text
汇报里每条“已验证”必须写出：验证对象、验证方法、证据位置（日志 / 截图 / 测试名）。
验证对象必须与你声明的对象一致——声明“屏幕上没有 X”就用屏幕最终像素，不要用中间量。
必须有一栏“没做 / 没验证”，写原因。有测试却没测到点子上的，明说。
```

检查清单（提交汇报前自问）：

1. 这个测试断言的对象，是我声明的那个对象吗？（案例 02：测试验证了裁剪矩形，不是屏幕上的星点。）
2. 去掉我的改动，这个测试会失败吗？（“去掉改动后新用例会失败，说明它测到了点子上”，同一会话里用过。）
3. 有没有静音的错误或被吞的返回码？（案例 08.1）
4. 前后对比里没量化的项，是否写成了“未测”？（案例 06：CPU 占用对比未量化，不能写成已测得。）
5. 有没有对错误假设下游的结论？（案例 01）

## 已验证效果

此后的汇报（案例 04、05、06）带有“没做完 / 没验证”一栏；本包 `report/metrics.md` 第 7 节“尚未测量的项目”和 `report/design_report.md` 第 9 节的状态表也按此写成。

## 失效条件

清单靠自觉执行；没有自动化检查时，仍可能漏掉第 1 条里“对象不一致”的细微情形，所以要配合真机验证（案例 02 靠真实截图发现）。

## 来源

案例 02（星点测试缺口）、案例 06（CPU 占用对比）、案例 08.1（静音错误）。
