# 工作流 5：硬件访问门控（hardware access gate）

**适用场景**：让模型编写或修改会访问 PL 寄存器、装载位流 / 内核模块、重启板子、删除板上数据的代码或操作。

## 用法

给模型的提示词：

```text
凡是访问 PL 的路径，先回答三个问题，再写代码：
1. 此刻这个地址是否有效？（窗口范围；设备状态；复位 / 握手信号电平）
2. 如果无效，调用者得到什么？（返回错误，而不是继续访问）
3. 谁会绕过这个门？（别的 ioctl、用户态直接映射、测试程序）
并为 (1) 的每个分支写一个测试。
装载 PL / 模块、重启、删除前，先问我确认：无人佩戴电极、刺激源关闭。
```

检查清单：

1. 寄存器索引有上限和白名单；窗口外一律拒绝（P-02）。
2. 已完成 / 复位中 / 故障状态一律拒绝访问，返回 `-EBUSY`（P-03）。
3. 位流 / 模块 / 应用成套发布，开机回执核对身份（P-07）。
4. 启动时不做“顺手同步”硬件配置，只在操作者动作时写（P-29）。
5. 同一块板子被别的会话使用时先协调（P-31）。
6. 删除按“拷到主机 → 逐文件校验 SHA → 再删 → 记台账”（P-24）。
7. 所有改动都配一个能在板上回放的测试程序（本项目：`board/tools/ssvep_ops_replay.c`，把仿真用的同一份操作程序在真实 PL 上回放）。

## 已验证效果

两次整机故障之后加入门控与白名单：板上回放 112,345 次操作 0 错误，重启后再回放仍 0 错误，两次整机重启的开机配对核验通过，11 分钟连续监测无丢包；
这些只证明这两类触发路径已封住。2026-11-03 的一次 ADC 数据超时故障（案例 09）属于不同机制，不在这个门控覆盖范围内。

## 失效条件

* 新增入口忘记接入门控；
* 故障来自硬件电气原因（供电、静电、EMI）而非访问时机；
* 没有板上回放程序可用时，只能靠主机仿真，风险更高。
