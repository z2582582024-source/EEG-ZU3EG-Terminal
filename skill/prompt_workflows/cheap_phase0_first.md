# 工作流 6：先做廉价的阶段 0（cheap phase 0 first）

**适用场景**：准备投入多日工作（新硬件、PL 改动、大重构）去追一个估计的收益之前。

## 用法

```text
在做 <大工程> 之前，设计一个“阶段 0”：只在主机上、用已有的公开数据、复现部署协议，
回答“收益是否存在、有多大”。写出：协议（与部署逐项对齐）、判据（多大的收益值得做）、
预计耗时（应远小于大工程）。阶段 0 之后再决定做不做。
不要因为“别的功能当天就做完了”而压缩新硬件的验证。
```

阶段 0 的设计要点：

1. **与部署逐项对齐**：窗口起点、检查点、阈值来源、目标子集、通道数。
2. **多种方案并列**：现用方案、候选方案、混合方案；给出每个设置下的差异，而不是只给最好的一个。
3. **先写判据**：例如“部署协议下平均收益 < 1 个百分点则不做”。
4. **结果入库**：脚本、数据 JSON、摘要都保留（`data/results/ssvep_template_study/`）。

## 已验证效果

阶段 0 显示混合模板在板上实际窗口起点下平均只提高 0.28 个百分点（窗口起点提前到 0.14 s 才有 +4.25），
因此没有实现约 6 天工作量的 DDR4 模板存储，也避免了一次在 CLB 98 % 占用下的额外 PL 构建。

## 失效条件

阶段 0 的协议与实板不一致时结论无效（所以第 1 条是重点）；收益不是准确率而是别的指标（如功耗）时需要换判据。
