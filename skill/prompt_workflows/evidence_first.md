# 工作流 2：证据优先（evidence first）

**适用场景**：回答“某信号 / 时钟 / 寄存器 / 配置是什么、来自哪里”这类设计事实问题；事故分析；写报告里的结论。

## 用法

给模型的提示词（可直接复制）：

```text
回答前先列出你要依据的文件与行（生产代码、约束、实测日志），按这个优先级：
生产 RTL 与约束 > 板上实测 > 设计文档 > 代码注释 > 历史候选 / 诊断顶层。
候选和诊断顶层只能当线索。结论后面写“依据：文件:行”；没有依据的写“未确认”。
如果发现之前的结论依据了低优先级来源，先更正，并列出所有受影响的下游结论。
```

步骤：

1. 找到**生产**顶层与约束（本项目：`src/pl/rtl/top`、`src/pl/constraints`），不要从历史里程碑目录取答案。
2. 同一事实至少对上两处：RTL 与实测（本项目：RTL 的 `÷(2×25)` 与板上 `interval_ns=1024000`）。
3. 发现错误时写勘误块（“以勘误为准”），旧文字保留，并逐条写影响：作废 / 不变。
4. 下一次涉及同一子系统的判断，先读生产代码，再开口。

## 已验证效果

案例 01：ADC_CLK 来源被更正后，采样间隔的推导（2.000 MHz ÷ 8192 = 244.140625 SPS，每样本 409,600 个 PL 周期）与板上日志一致，
此后频率格审计、窗口对齐设计都建立在这一数字上，没有再出现来源反复。

## 失效条件

* 没有生产源码（只有二进制）时，优先级链条断裂——只能标“未确认”。
* 生产代码本身有错：要靠实测发现，所以第 2 步要求两处互证。
