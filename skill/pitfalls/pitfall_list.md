# 踩坑清单

每条都写：**适用场景**、**检查项（怎么用）**、**已验证效果**、**失效条件**、**来源**（从哪次失败或观察得到）。
“已验证效果”只写在本项目里实际观察到的结果；没有验证过的写“未单独验证”。案例编号指 `report/ai_collaboration/episodes/` 下的 `epNN_*.md`。

## 使用方法

1. 开始一类任务前，按场景在上表里找对应条目（硬件访问 / 仿真构建 / 指标表述 / 事故分析 / 工具链）。
2. 把“检查项”当成**提交前的清单**逐条回答；能用脚本检查的用 `skill/check_scripts/`。
3. 新发现的坑按同样的六列补进来，并写明来源案例，没有验证过的“已验证效果”写“未单独验证”。
