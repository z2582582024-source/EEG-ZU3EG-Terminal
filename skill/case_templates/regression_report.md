# 案例模板：回归与更正报告（regression / correction report）

**适用场景**：用户报告“某功能失效了”，或模型发现自己之前的结论 / 数字错了。**用法**：复制模板填写；先承认、再定位、再给证据。
**已验证效果**：案例 03、04、06 用这个结构，每次更正都带“影响了什么 / 没影响什么”。**失效条件**：错误来自用户给的错误前提时，需要先和用户确认前提，而不是直接“更正”。

```markdown
# 更正 / 回归：<一句话>

## 1. 现象或错误说法
- 原文 / 现象（逐字引用，不改写）

## 2. 原因（我造成的，还是外部的）
- 机制：<例如：失败路径静默 return；依据了旧诊断顶层的注释>
- 为什么没有被测试 / 自查发现

## 3. 更正后的正确结论
- 正确表 / 正确事实（完整，不是只改一个数）
- 依据：文件:行 / 数据手册章节 / 官方报告

## 4. 影响面
| 下游结论 / 文档 | 受影响吗 | 处理 |
| --- | --- | --- |

## 5. 验证
- 新增测试（并说明去掉改动时它会失败）
- 板上 / 硬件上**没有**验证的部分（明确写）

## 6. 固化
- 对应的检查项
```
